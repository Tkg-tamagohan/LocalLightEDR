# LocalEDR 仕様決定記録

本記録は [ledr_artifact.html](../ledr_artifact.html) の設計レビューで抽出した要協議事項 A〜P に対する確定仕様を一覧化したものである。
決定内容は 2026-11-18 にユーザーが全推奨案を受け入れた結果に基づき、各決定は [implementation-plan.md](implementation-plan.md) から `決定記録 L-01` 〜 `決定記録 L-16` の ID で参照する。

## 確定仕様一覧

| ID | 対象領域 | 項目 | 決定内容 | 根拠 |
| :--- | :--- | :--- | :--- | :--- |
| L-01 | 全体 | ターゲット OS の初期実装範囲（項目 A） | Phase 1〜4 の初期実装対象を Windows 10 および Windows 11（x86_64）専用とし、`crates/ledr-proto` のトレイト境界のみ将来 Linux（Aya eBPF）へ拡張できる抽象化に留める。 | 個人開発規模で 3 OS の特権カーネル API を同時実装すると検証負荷が発散し、特に macOS の EndpointSecurity は Apple の Entitlement 審査が配布と実地検証の障壁になるため。 |
| L-02 | Layer 1 | 機密ファイル保護の位置づけ（項目 B） | カーネルドライバを書かない方針を維持し、ETW `FileIo` と `NtSuspendProcess` を読み取り直後の即時凍結による後続窃取と外部送信の封じ込めと位置づけ、おとりファイル検知、不審コマンドライン検知、および Phase 3 の WFP 通信遮断を併用する。 | EV コードサイニング証明書や BSOD リスクを伴うミニフィルタドライバ開発を回避しつつ、読み取り後の外部 C2 送信を遮断することでインフォスティーラーの実害を防げるため。 |
| L-03 | Layer 1 | WFP アウトバウンド制御と承認方式（項目 C） | 高リスクパス（`Downloads` や `Temp` 配下の実行ファイル）およびスクリプトインタプリタ（`powershell`、`node`、`python` 等）は事前に WFP 動的ブロックフィルタまたは厳格ルールを適用し、一般パスの未知プロセスによる初発外部通信は検知直後に `NtSuspendProcess` と WFP 動的ブロックフィルタを追加してユーザー承認後に解除と再開を行うハイブリッド方式とする。 | カーネル Callout ドライバなしでサプライチェーン攻撃や LOTL の初発通信漏れを防ぎつつ、通常アプリケーションの利便性を損なわないため。 |
| L-04 | Layer 1〜3 | ホワイトリストと許可ルールの識別基準（項目 D） | 署名済みバイナリは正規化パスパターンと Authenticode 電子署名（Signer Subject と Root Thumbprint）による許可を選択可能とし、未署名バイナリは正規化実行ファイルパスと SHA-256 ハッシュの一致を必須とする 2 階層モデルを採る。 | 主要ブラウザや開発ツールの自動更新でハッシュが変わるたびにアラートが頻発する運用破綻を防ぎながら、未署名バイナリの差し替えや改ざんを厳密に検出できるため。 |
| L-05 | Layer 1 | Folder Canary の対象パス指定モデル（項目 E） | 保護対象パスを既定認証パステンプレート（Chrome、Edge、Brave、Firefox の `Cookies`、`Login Data`、`Local State`、`~/.ssh/*`、`~/.aws/credentials`、`~/.config/gcloud/*`）とユーザーが登録した開発ルート配下の `.env*` ファイル名一致の 2 系統とする。 | ディスク全体の走査や監視を行わずに、ETW コールバック内の軽量な文字列比較だけで主要認証ストアと開発秘密ファイルを保護できるため。 |
| L-06 | Layer 1 | おとりファイル設計と削除管理（項目 F） | `%USERPROFILE%\Documents`、`Desktop`、`Pictures` の直下に辞書順先頭となる名称（例として `!00_LocalEDR_Canary_DoNotEdit.docx`）を自動生成し、SQLite で追跡管理してアンインストール時に自動削除する。発火条件は Read を除いた書き込み、削除、およびリネームのみに限定する。 | ランサムウェアの暗号化走査で最初期に検知しつつ、Windows Search インデクサやバックアップソフトによる読み取り誤検知を排除するため。 |
| L-07 | Layer 1〜4 | サスペンド範囲と 60 秒未応答時の状態遷移（項目 G） | おとりファイル書込時は対象と子孫プロセスツリー全体を即時サスペンドし、機密ファイル Open 時は対象プロセスを即時サスペンドする。通知後 60 秒間（設定変更可）未応答の場合はサスペンド状態を維持したまま `EXPIRED_SUSPENDED` へ遷移させ、画面上の選択肢は強制終了と永続遮断、今回のみ許可、および永続ルール許可の 3 段階とする。 | 離席時の自動再開による情報漏洩と、誤検知時の自動強制終了による編集データ消失の両方を防ぐため。 |
| L-08 | Layer 4 | Session 0 からの通知と UI 起動方式（項目 H） | 平常時の UI メモリ消費ゼロを維持するため、アラート発火時のみサービスが `WTSQueryUserToken` と `CreateProcessAsUser`（Medium Integrity のログオンユーザートークン）で `ledr-ui.exe --notify <alert_id>` をワンショット起動し、WinRT トースト通知を出して即終了する。 | 普段は UI プロセスを常駐させない原則を守りながら、Session 0 隔離と非 SYSTEM 権限実行の安全境界を両立できるため。 |
| L-09 | Layer 2, 4 | Named Pipe IPC の認可と偽装防止（項目 I） | Named Pipe（`\\.\pipe\localedr-ipc`）の DACL を `SYSTEM`、管理者、および対話ユーザーに絞った上で、状態変更系の IPC コマンド受信時はデーモン側で `GetNamedPipeClientProcessId` を呼び、接続元が管理者保護領域（`C:\Program Files\LocalEDR\ledr-ui.exe`）の正規署名またはハッシュ一致バイナリであることを検証して認可する。 | 緊急トリアージ時のワンクリック操作を毎回 UAC ダイアログで妨げることなく、同セッション内の非特権マルウェアによる改変コマンド偽装を阻止できるため。 |
| L-10 | Layer 2 | 有界バッファ上限とドロップ規約（項目 J） | デーモン内チャネルを高優先度レーン（容量 1,024 でカナリア、おとり書込、AMSI、未知外部通信、およびプロセス生成と終了を扱いドロップ禁止）とテレメトリレーン（容量 8,192 で定常 DNS と一般通信ログを扱い満杯時は古いログを破棄して件数を記録）の 2 レーン構成（合計約 2〜3 MB）とする。 | 常駐メモリ 20 MB 上限を順守しながら、高負荷ビルド時でも防御イベントとプロセス系譜の欠損を防ぐため。 |
| L-11 | Layer 3 | SQLite TTL と親プロセス孤児化防止（項目 K） | 既定の保持期間を 14 日間（設定で 7〜30 日へ変更可）とし、`processes` テーブルのパージ対象を終了済みかつ `exited_at_ms` が期限超過であり、未パージの子プロセスおよび未解決アラートから参照されていない行に限定する。 | インシデント調査に十分な 2 週間分の履歴を確保しつつ、長期起動した親プロセスの欠損によるツリー表示崩れを防ぐため。 |
| L-12 | Layer 2 | 軽量 Sigma サブセット範囲（項目 L） | 対象範囲を単一イベントおよびインメモリの直近親プロセス文脈に対するフィールド照合（`Image`、`ParentImage`、`CommandLine`、`DestinationIp`、`QueryName`、`TargetFilename` への前方一致、後方一致、部分一致、`all` 結合、事前コンパイル済み制限付き正規表現）に絞り、起動時に Aho-Corasick オートマトンへコンパイルする。 | メモリ消費を約 2 MB 以内かつ 1 イベント数マイクロ秒で評価でき、主要な LOTL 検知ルールをそのまま利用できるため。 |
| L-13 | Layer 4 | 3 つのコアビューと 5 秒隔離導線（項目 M） | UI を「1. アラートトリアージビュー」「2. プロセス系譜と通信フライトレコーダービュー」「3. 防御ポリシー、カナリア、ブラウザシールド管理ビュー」の 3 ビュー構成とし、通知クリック時は画面遷移なしで 1 画面目を開いて系譜、通信先、MOTW とワンクリック隔離ボタンを同画面に配置する。 | 通知確認後のクリック操作とページ遷移を減らし、5 秒以内での状況把握と隔離操作を完結させるため。 |
| L-14 | Layer 2, 4 | NRD とホモグラフ判定のデータソース（項目 N） | 通信ごとの外部照会は行わず、1. デーモンが 1 日 1 回取得する公開 NRD フィード（登録 14 日以内）のローカルキャッシュ照合、2. ローカル DNS 履歴にない初見ドメイン判定、および 3. Punycode（`xn--`）と主要ブランド名との編集距離によるホモグラフ判定を組み合わせる。 | ブラウザや通信処理へ待機遅延や訪問先ドメインの外部露出を持ち込まず、ローカル環境内で高速にフィッシング兆候を判定できるため。 |
| L-15 | Chrome 拡張 | Pastejacking（ClickFix）検知の発火条件（項目 O） | 警告発火をコピー文字列が危険な LOTL コマンド特徴量（`powershell`、`pwsh`、`cmd`、`mshta`、`certutil`、`curl` パイプ経由シェル実行、`iex`、`-enc`、不可視制御文字や改行注入）を含む場合、またはユーザーの DOM 選択範囲（`getSelection()`）とクリップボード書き込み文字列が不一致の場合に限定する。 | 開発者の日常的なコードコピー作業を妨げずに、ユーザーに気付かせず悪性コマンドを貼らせる ClickFix や Pastejacking のみを捕捉できるため。 |
| L-16 | Layer 2〜3 | Windows Service 復旧と自己保護方針（項目 P） | `LocalSystem` サービスとして SCM 回復オプション（失敗時 1 秒後に自動再起動）を設定し、設定、ルール、および SQLite DB を `C:\ProgramData\LocalEDR\`（DACL を `SYSTEM` と管理者のみ書込許可に設定）へ格納する。 | カーネル保護ドライバ（ELAM や PPL）を書かない制約のもとで、OS 標準の権限分離のみでサービス停止攻撃と設定改ざんを阻止できるため。 |
